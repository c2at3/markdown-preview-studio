API Documentation

A single endpoint for third-party tools to create, update, and delete notes in Markdown Preview Studio.

Authentication

Requires an API key sent as a Bearer token. Create and revoke keys from the app: click the key icon in the sidebar footer.

Authorization: Bearer mdpk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
The full key is shown only once, right after creation. If you lose it, revoke it and create a new one - there is no way to recover a lost key.
An API key can only call the one endpoint documented on this page. Everything else in the app (browsing the sidebar, sharing, templates, managing keys) is only available to a logged-in session - an API key can't touch it.

The endpoint

Addresses a file by a human-readable folder path + filename instead of database ids. POST creates it, or overwrites it in place (same id, no duplicate) if one already exists there. DELETE removes it.

Create or update

POST/api/files/upload

If no file named filename exists yet in folder, it's created. If one already exists there, it's overwritten in place - this is how you "re-upload"/update a note from a script.

FieldTypeNotes
filenamestringRequired
folderstringPath like "TEST/Bug bounty" (nested folders separated by /). Omit for root
auto_createbooleanDefault true - creates any missing folder in the path. Set false to fail with 404 instead of creating anything
contentstringMarkdown source. On create, defaults to empty. On update, omit to leave the existing content untouched
iconstringOne of the icon names below
color_filestringOne of the color names below (not a hex code - see Icons & colors)
color_folderstringOne of the color names below. Applied only to folders newly created by this call - existing folders keep their color

Response - action is "created" or "updated"; created_folder_ids is empty when every folder in the path already existed:

{ "id": "...", "name": "Report 001 - XSS", "folder_id": "...", "content": "...",
  "icon": "bug", "icon_color": "#ef4444", "action": "created", "created_folder_ids": ["...", "..."] }

Delete a file

DELETE/api/files/upload

Same folder + filename as a JSON body. Folders are never auto-created for a delete - a missing folder or file just returns 404.

{ "ok": true, "deleted": "file", "id": "..." }

Delete a folder

Same call without filename - deletes only the last folder in the path (not its parents). Files and sub-folders inside it are moved to root, not deleted, matching the app's own "delete folder" behavior.

{ "ok": true, "deleted": "folder", "folder_id": "..." }

Errors

Errors are returned as JSON with an error message and a non-2xx status code.

HTTP/1.1 400 Bad Request
{ "error": "Invalid color_file: \"#ef4444\". Must be one of: red, orange, yellow, green, blue, purple, pink, teal, gray" }
StatusMeaning
400Missing filename; an icon/color_file/color_folder outside the fixed set below; or nothing to delete
401Missing or invalid API key
403Called a URL other than /api/files/upload
404auto_create: false and the folder path doesn't fully exist yet, or deleting a file/folder that doesn't exist
